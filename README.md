# CoffeeSOS Backend

Golang API for **CoffeeSOS** (Coffee Simple Operating System): a multi-tenant
platform that runs many cafe brands and their stores. One backend serves the
Admin web, the POS (Flutter, tablet + mobile), the barista screen and the
customer app.

## Stack

| Concern      | Choice                                                    |
|--------------|-----------------------------------------------------------|
| HTTP         | Gin                                                       |
| Database     | PostgreSQL 16 via pgx/v5, queries generated by sqlc       |
| Migrations   | golang-migrate, embedded in the binary (`api migrate`)    |
| Auth         | JWT (HS256) carrying `brand_id`, `store_id`, `role`       |
| Realtime     | gorilla/websocket hub with brand and store rooms          |
| Config       | environment variables (+ optional `.env`)                 |

## Layout

```
cmd/api            entrypoint: serve | migrate | seed
internal/app       router, middleware wiring
internal/auth      JWT issue/verify, login, RequireAuth / RequireLevel
internal/tenant    Principal + brand/store scope resolution
internal/brand     platform + brand admin (brands, stores, users)
internal/menu      categories, items, option groups, store menu
internal/realtime  WebSocket hub
internal/db        sqlc output (do not edit) + queries/*.sql (edit these)
internal/seed      platform admin + demo tenant "Daily Bean"
migrations/        SQL migrations (embedded)
```

## Multi-tenant rules

* Every business table has `brand_id`; store-level data also has `store_id`.
* Composite foreign keys (`(category_id, brand_id)`, `(store_id, brand_id)`)
  make cross-brand references impossible at the database level.
* Roles: `staff` (10) < `store_manager` (20) < `brand_owner` (30) < `platform_admin` (100).
* Route groups: `/api/v1/platform` (platform admin), `/api/v1/admin` (brand),
  `/api/v1/pos` (store), `/api/v1/app` (customers).
* Platform admins act on a brand with `X-Brand-ID`; managers/owners act on a
  store with `X-Store-ID`. Staff are pinned to their store by the token.

## Run locally

```bash
cp .env.example .env            # edit DATABASE_URL if needed
createdb coffeesos              # any Postgres 16
go run ./cmd/api migrate
go run ./cmd/api seed           # prints the platform admin password once
go run ./cmd/api serve          # http://localhost:8080
```

Demo tenant after `seed`: brand **Daily Bean**, store **Quận 3**,
`owner@dailybean.local` / `staff@dailybean.local`, password `DailyBean123`.

Regenerate query code after editing `internal/db/queries/*.sql` or migrations:

```bash
brew install sqlc && make sqlc
```

## API (v1)

| Method | Path                                      | Who              |
|--------|-------------------------------------------|------------------|
| GET    | /healthz                                  | public           |
| POST   | /api/v1/auth/login                        | public           |
| GET    | /api/v1/auth/me                           | any user         |
| GET    | /ws?token=…                               | any brand user   |
| GET    | /api/v1/platform/brands                   | platform admin   |
| POST   | /api/v1/platform/brands                   | platform admin   |
| POST   | /api/v1/platform/brands/:brandId/stores   | platform admin   |
| POST   | /api/v1/platform/brands/:brandId/users    | platform admin   |
| GET    | /api/v1/admin/brand                       | store manager +  |
| PUT    | /api/v1/admin/brand                       | brand owner +    |
| GET    | /api/v1/admin/stats                       | store manager +  |
| GET    | /api/v1/admin/stores                      | store manager +  |
| POST   | /api/v1/admin/stores                      | brand owner +    |
| GET    | /api/v1/admin/users                       | brand owner +    |
| POST   | /api/v1/admin/users                       | store manager +  |
| POST   | /api/v1/admin/uploads                     | store manager +  |
| GET    | /api/v1/admin/menu/categories             | store manager +  |
| POST   | /api/v1/admin/menu/categories             | brand owner +    |
| PATCH  | /api/v1/admin/menu/categories/:id         | brand owner +    |
| GET    | /api/v1/admin/menu/items                  | store manager +  |
| POST   | /api/v1/admin/menu/items                  | brand owner +    |
| PUT    | /api/v1/admin/menu/items/:id              | brand owner +    |
| PATCH  | /api/v1/admin/menu/items/:id/availability | store manager +  |
| GET    | /api/v1/pos/menu                          | staff +          |
| GET    | /api/v1/app/stores/:storeId/menu          | public           |

Toggling availability broadcasts `menu.item.availability` to the brand room on
`/ws`, so POS terminals and apps drop sold-out items immediately.

### File uploads (Cloudflare R2)

`POST /api/v1/admin/uploads` takes `multipart/form-data` with `file` (JPEG,
PNG, WebP, GIF; SVG for logos) and `kind` = `menu-items` | `brand-logos`
(logos: brand owner only), max 10 MB, and answers `{key, url}`. The caller then
saves `url` as the item's `imageUrl` or the brand's `logoUrl`. Objects live at
`brands/{brandId}/{kind}/{uuid}.{ext}` in the bucket and are served through the
bucket's custom domain (`R2_PUBLIC_URL`) with an immutable cache header.

Configure with `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,
`R2_BUCKET`, `R2_PUBLIC_URL` (see `.env.example`). When unset the endpoint
returns 503 `storage_not_configured` and everything else keeps working.

## Deploy (Docker host)

```bash
make deploy                     # rsync to hector_vps:/root/coffeesos, build, up, seed
make logs
```

`scripts/deploy.sh` generates `/root/coffeesos/.env` with random
`POSTGRES_PASSWORD`, `JWT_SECRET` and `SEED_ADMIN_PASSWORD` on first run.
Postgres and the API both listen on `127.0.0.1` of the host only
(`API_BIND=127.0.0.1`); nginx terminates TLS and proxies:

* https://dev.coffeesos.online/api/v1/...  -> API
* wss://dev.coffeesos.online/api/ws         -> WebSocket hub
* https://dev.coffeesos.online/api/healthz   -> health

The site config is `deploy/nginx/dev.coffeesos.online.conf` (copy to
`/etc/nginx/conf.d/`, then `certbot --nginx -d dev.coffeesos.online`).
